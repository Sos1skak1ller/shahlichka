# Персональный игровой слой Х5 Клуб

Игровой слой поверх программы лояльности: аватар растёт от **суммы экономии** по
подтверждённым чекам (не от активности в приложении), раз в неделю выдаётся
персональный челлендж, подобранный объяснимым ML-пайплайном (шаблоны + ранжирование,
**без LLM**), работает реферальная программа с отложенной наградой и персональное
ранжирование акций. Каждый чек и реферал проходит синхронный антифрод-скоринг с
фиксированным порогом; экономика награды считается и лимитируется заранее. Когортная
симуляция 1–10 тыс. синтетических профилей (treatment vs control) на том же расчётном
коде даёт метрики пилота и ROI.

Спека, план и задачи: `specs/001-gaming-layer/`. Конституция проекта:
`.specify/memory/constitution.md`. Рабочее ТЗ: `docs/TZ_X5_gaming_layer.md`.

## Структура

| Модуль | Назначение |
|---|---|
| `engine/` | Детерминированное расчётное ядро (Python, без I/O). Один код обслуживает и демо-фикстуры, и симуляцию (FR-031). |
| `sim/` | Синтетическая популяция + когортная симуляция. Использует `gaming_engine`. |
| `fixtures/` | Скриптовый демо-сценарий и сгенерированные экранные JSON (`fixtures/out/`). |
| `web/` | Демо-фронт клиента + отдельный Promo Studio (React + TS), без обязательного бэкенда. |
| `specs/001-gaming-layer/contracts/` | JSON Schema — единый источник истины формы данных. |

## Запуск

Требуется [`uv`](https://docs.astral.sh/uv/) и Node 20+.

```bash
# 1. Python-окружение (Python 3.11 ставится автоматически)
uv sync --group dev

# 2. Тесты движка и симуляции
uv run --project engine pytest engine/tests -q
uv run --project sim    pytest sim/tests -q

# 3. Пересобрать демо-фикстуры из скриптового сценария
uv run python -m fixtures.build

# 4. Когортная симуляция + отчёт по contracts/simulation-report.schema.json
uv run python -m gaming_sim.runner --population 10000 --weeks 4 --seed 42 --out sim/out/run_10k.json

# 5. Инвариант паритета demo ↔ sim (SC-006 / FR-031)
bash scripts/check-parity.sh

# 6. Демо-фронт клиента и Promo Studio (без бэкенда)
cd web && npm install && npm run test && npm run dev
```

После запуска клиентский прототип доступен на `/`, а платформа ввода промо — на
`/promo-studio`. Promo Studio хранит изменения в `localStorage` и умеет импортировать
и экспортировать общий JSON-пул. Демо-промо помечены `demo_only` и должны быть заменены
после проверки маркетологом. В карточках и редакторе доступен демонстрационный
аналитический контур: прогноз охвата, uplift и экономики, а также пример результата
A/B-теста. Эти значения синтетические и не являются фактическими данными X5. Вкладка
«В X5 Рост» показывает назначение промо на тестового M2-клиента; сохранённое одобренное
промо можно опубликовать, после чего его персональная карточка появляется на клиентском `/`.

## Осознанные отклонения от буквального текста кейса (для защиты)

1. **LLM-агент → объяснимый ML-пайплайн** (шаблоны + логрег-ранжирование). Тот же
   функциональный результат — персональный челлендж по истории покупок — но
   воспроизводимо и объяснимо, без риска галлюцинаций на демо. См. `research.md` R3.
2. **Рейтинг экономии (дом/район/город) убран из скоупа целиком.** Честная
   k-анонимность на уровне района/дома невыполнима на синтетике 1–10 тыс. пользователей
   без искусственного завышения кластеров. Остаются 3 экрана (профиль/аватар, челлендж,
   реферал) — в допустимом диапазоне «3–4». См. `spec.md` FR-007.

## Ключевые принципы (конституция v1.0.0)

- **Экономия ведёт к награде, никогда наоборот** — уровень аватара определяется только
  `saved_amount`.
- **Объяснимость важнее сложности** — простые интерпретируемые модели, фиксированный
  порог антифрода с объяснением по фиче, никакого LLM в продуктовом пути.
- **Экономика награды считается заранее** — недельный бюджетный потолок, инвариант
  «стоимость награды ≤ ожидаемый прирост маржи».
- **Антифрод и симуляция обязательны** — один код для демо и симуляции.
- **Демо-first, только синтетика** — статичные фикстуры, ноль сетевых зависимостей на
  сцене, никаких ПДн, в названии нет «ИИ»/«AI».
